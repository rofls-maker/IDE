# RofloIDE

Маленькая IDE на WPF. Не замена VS Code и не пытается ей быть — скорее блокнот
с деревом файлов и встроенной консолью, чтобы открыть папку с сишными
файлами, что-то поправить, собрать через gcc и тут же посмотреть вывод,
не переключаясь между окнами.

Проект сырой. Многое сделано по принципу "чтобы работало", а не красиво.

## Что есть

Окно поделено на три части: слева дерево проекта, справа редактор, снизу
терминал. Тема тёмная, цвета подсмотрены у VS Code.

Дерево строится из выбранной папки со всеми вложенными. Рядом с именами
рисуются иконки по расширению — обычные emoji, никаких ресурсов (для `.cs`
просто буквы `C#`). На папке висит `FileSystemWatcher`: если снаружи что-то
создать, удалить или переименовать, дерево само перестроится примерно через
полсекунды. Задержка специально, чтобы не перерисовывать на каждое событие,
когда файлов прилетает пачка.

Редактор — обычный `TextBox` с Consolas. Подсветки синтаксиса нет, нумерации
строк тоже нет (стиль для неё в `App.xaml` лежит, но никуда не подключён).
Заголовок окна показывает имя файла и звёздочку, если есть несохранённые
правки. При закрытии спросит, сохранять ли.

Терминал — это `cmd.exe`, запущенный без окна с перенаправленными потоками.
Команда вводится в строку внизу, вывод идёт в `RichTextBox` с раскраской:
свои команды зелёным, stderr красным, служебные сообщения жёлтым. Кодировка
866, чтобы русский вывод не превращался в кракозябры. Стартует в домашней
папке, после открытия проекта сам делает `cd` в него. Вывод обрезается после
500 абзацев, иначе `RichTextBox` начинает заметно тормозить.

Кнопка "Скомпилировать C" сохраняет текущий файл и отправляет в тот же
терминал `gcc file.c -o file.exe`. Никакой магии, gcc должен быть в PATH.

Необработанные исключения ловятся глобально и показываются в `MessageBox`.
Если ошибка в UI-потоке — приложение живёт дальше, если в фоновом — покажет
сообщение и всё равно упадёт, тут ничего не сделаешь.

## Горячие клавиши

- `Ctrl+N` — новый файл через диалог (если проект открыт, сразу в его папке)
- `Ctrl+Shift+N` — новый пустой файл, без сохранения на диск
- `Ctrl+O` — открыть файл
- `Ctrl+S` / `Ctrl+Shift+S` — сохранить / сохранить как
- `F5` — перечитать дерево проекта
- `Ctrl+F5` — скомпилировать текущий `.c`
- `Ctrl+Enter` — выполнить команду в терминале (обычный Enter в строке ввода
  тоже работает)
- `Ctrl+Z`, `Ctrl+A` — как обычно

## Сборка

Нужен Windows и .NET 8 SDK. Открываешь `IDE.sln` в Visual Studio 2022 и
жмёшь F5, либо из консоли:

```
dotnet build IDE.sln -c Release
```

Для кнопки компиляции нужен gcc — MinGW-w64, MSYS2, без разницы, лишь бы
`gcc --version` отрабатывал из обычного cmd.

## Про editor_core.dll

В `NativeMethods.cs` лежат P/Invoke-обёртки над нативной библиотекой
`editor_core.dll`: открыть файл, получить количество строк, достать строку по
индексу, заменить строку, узнать, есть ли на строке ошибка, скомпилировать.
`VirtualLineList` заворачивает это в `IList<string>`, чтобы потом отдать
виртуализированному списку вместо редактора.

Сейчас всё это не используется. Редактор читает файл через
`File.ReadAllText` и держит текст в `TextBox`. Самой библиотеки в репозитории
нет, и если её не положить рядом с exe — ничего страшного, до вызовов дело не
доходит.

План такой: хранение текста и разбор ошибок уезжают в нативный код, WPF
остаётся только отрисовка. Когда это заработает, `TextBox` уйдёт. Если будешь
класть dll — собирай проект под x64, чтобы разрядность совпала.

## Известные косяки

- Выбор папки проекта сделан через `OpenFileDialog`: надо зайти в нужную
  папку и нажать "Открыть", в поле имени стоит заглушка "Папка". Костыль,
  по-хорошему надо заменить на `OpenFolderDialog`, в .NET 8 он уже есть.
- Дерево пересобирается целиком при любом изменении. На больших папках
  (`node_modules` и подобное) будет заметно.
- Клик по файлу в дереве сразу открывает его, не спрашивая про несохранённые
  изменения в текущем.
- Заголовок окна в одном месте `RofloIDE`, в другом `CodeIDE`. Руки не
  дошли.
- Терминал — не полноценная консоль: нет истории команд, стрелок,
  автодополнения. Программы, которые сами читают stdin, получат его через ту
  же строку внизу, но удобным это не назвать.
- Вкладки, поиск по файлу, несколько открытых файлов — ничего этого нет.

## Что дальше

Примерно в таком порядке:

1. Довести `editor_core` и заменить `TextBox` на свою отрисовку строк
2. Нумерация строк
3. Подсветка синтаксиса, хотя бы для C
4. Подсветка ошибок компиляции прямо в тексте
5. Нормальный диалог выбора папки
